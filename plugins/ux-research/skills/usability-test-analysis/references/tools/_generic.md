# Any other tool

For a tool with no profile here, or a spreadsheet the team built by hand.

**Last updated:** 16 November 2026

---

## Route

1. Get a CSV. From Excel, Numbers or Google Sheets: export or download as CSV. Several sheets mean
   several CSVs; ask which holds what.
2. Run `check.py columns` and propose a type for every column, using the table in SKILL.md Step 2.
3. Decide the layout:
   - **Wide**: one row per participant, one column per question. Most tools' default.
   - **Long**: one row per participant per question, with a question column and an answer column.
   - **Anything else** (one sheet per task, merged header rows, one row per session note): reshape it
     into one of the two with the user before analysing, and say what you did.
4. Pair every rating with its task, and every task with its outcome, transcript and follow-up
   columns. Confirm the pairing.

## Questions to ask

- What did each rating question say, exactly, and what were its endpoints?
- Is task success recorded, and who judged it: the participant, a moderator, or the tool?
- Were participants thinking aloud?
- Are transcripts or recordings available outside the spreadsheet?
- Is anyone in the file who should not be analysed: a pilot, a colleague, a duplicate?

## What to watch for

- **A tool's "success" is often self-reported.** If the participant clicked "I completed this", it is
  a stated measure.
- **Time on task under think-aloud is inflated** and cannot be compared with silent norms.
- **A tool's own AI summary is not data.** Analyse the responses.

If the user's tool comes up often, propose a profile for it (SKILL.md, Proposing an addition).
