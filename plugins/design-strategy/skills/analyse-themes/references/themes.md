# Theme vocabulary

The 12 design strategy themes used by `analyse-themes` and, through them, by the lever library
in the companion `define-levers` skill.

Broad enough to apply to any interface: conversion pages, onboarding flows, dashboards, product
UIs, settings, apps.

Detect themes from what you actually observe. This list is a guide, not a constraint.

**This is a first pass and is expected to change.** Adding, renaming or removing a theme follows
the approval process in `SKILL.md`. Nothing is written here without the user's explicit approval.

Changing a theme name here breaks the mapping in the `define-levers` library, which refers to
themes by name. Update both.

---

| Theme | What it means |
|---|---|
| **Trust** | The page builds confidence through transparency, reliability signals, security indicators, or demonstrating credibility. Includes: privacy statements, testimonials from named sources, "cancel anytime", audit trails, data ownership signals. |
| **Informative** | The page teaches the user, features, how things work, what's included, what's possible. The strategy is: if the user understands, they will act. Includes: feature lists, explainer copy, pricing breakdowns, content previews. |
| **Momentum** | The page keeps the user moving forward through continuity, progress prompts, streaks, or next-step signals. Can include urgency (time pressure, scarcity) as a subtype. The strategy is: friction kills action, so maintain flow. Includes: saved state, "continue where you left off", next-step prompts, countdowns, one-click checkout, uninterrupted flows. |
| **Ease** | The page reduces the effort required to act, cognitively, physically, or psychologically. Includes: simple choices, familiar patterns, pre-populated structure, sensible defaults, "try before you commit" mechanics. |
| **Validation** | The page uses signals from others, peers, experts, or the system itself, to confirm the user is making the right choice. Includes: reviews, subscriber counts, awards, usage stats, system feedback ("10,000 teams use this"). |
| **Identity** | The page aligns with who the user believes they are or wants to be. The strategy is: this is for someone like you. Includes: values-led copy, community framing, aspirational imagery, worldview alignment. |
| **Orientation** | The page tells the user where they are, what they can do, and what matters most right now. Includes: clear hierarchy, status surfaces, "you are here" signals, post-login states, onboarding entry points. |
| **Personalisation** | The page adapts to what it knows about the user, making the experience feel built for them specifically. Includes: recommended content, role-specific views, adaptive defaults, history-aware surfaces. |
| **Control** | The page gives the user meaningful agency over their environment, output, or data. Includes: customisation options, keyboard shortcuts, export capabilities, filter and sort controls, permission settings. |
| **Delight** | The page uses unexpected moments of craft to create emotional resonance beyond the functional task. Includes: animation, micro-copy, sound, visual surprise, playful interactions. |
| **Progress** | The page makes advancement visible, creating a feedback loop that motivates continued use. Includes: completion meters, XP bars, streaks, checklists, before/after comparisons. |
| **Clarity** | The page removes ambiguity so users know what an action will do before they take it. Includes: consequence-specific confirmations, inline format guidance, explicit state labelling, plain-language copy. |
